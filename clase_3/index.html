Ruta de la Clase 3

    FastAPI + Supabase

    De memoria volatil a persistencia real

    En la Clase 2 la API podia crear, listar, actualizar y eliminar datos, pero esos datos vivian en una lista temporal. En la Clase 3 esa misma API evoluciona: ahora guarda informacion en Supabase.

    Idea central

    Cambiaremos items_db = [] por una tabla real de PostgreSQL. Las rutas seguiran recibiendo peticiones HTTP, pero la persistencia dejara de depender de la memoria del servidor local.

    1 · Hilo conductor

    La Clase 3 no empieza desde cero: expande lo que ya construimos

    Clase 2

    • Modelos Pydantic para validar entradas y respuestas.
    • Rutas con APIRouter para organizar endpoints.
    • CRUD funcional usando una lista en memoria.
    • Separacion inicial por carpetas y servicios externos.

    Clase 3

    • Los modelos se ajustan para trabajar con UUID y fechas.
    • Las rutas delegan el acceso a datos en una capa de servicio.
    • El CRUD escribe y lee desde una tabla de Supabase.
    • La estructura agrega configuracion, base de datos y servicios.

    No repetiremos que es FastAPI, BaseModel o APIRouter. Los usaremos como herramientas conocidas para resolver el nuevo problema: persistir datos.

    2 · Apertura

    Si una API guarda productos en una lista de Python, ¿que ocurre cuando reiniciamos el servidor?

    La lista vuelve a estar vacia Se pierde el historial Los clientes no pueden confiar en el sistema No sirve para produccion Necesitamos una base de datos

    3 · El problema

    La RAM es rapida, pero no es memoria permanente

    1. Inicia Uvicorn Python carga el codigo y crea la variable items_db = [].
    2. Llegan peticiones Los datos se agregan a esa lista mientras el proceso esta vivo.
    3. Se detiene el servidor La memoria del proceso se libera al cerrar la terminal o recargar el programa.
    4. Todo comienza otra vez Al reiniciar, Python crea una lista nueva y los datos anteriores ya no existen.

    4 · Analogia

    De la libreta temporal al archivo de biblioteca

    Una lista en memoria se parece a escribir prestamos de libros en una hoja que queda sobre el escritorio: funciona por un momento, pero se pierde si alguien la bota o se cierra la sala.

    Una base de datos se parece al sistema oficial de la biblioteca: cada registro queda guardado, puede buscarse despues y no depende de que una persona recuerde lo ocurrido.

    Traduccion al backend

    Supabase sera nuestro archivo permanente. FastAPI seguira siendo la puerta de entrada, pero los datos viviran en PostgreSQL.

    5 · CRUD persistente

    Los verbos HTTP ahora modifican filas de una tabla

    POSTInserta una nueva fila en items. GETConsulta una o varias filas existentes. PUTActualiza una fila filtrando por id. DELETEElimina una fila filtrando por id.

    La ruta HTTP no desaparece: cambia lo que hace por dentro. En lugar de modificar una lista local, llama a un servicio que conversa con Supabase.

    6 · Persistencia

    Supabase nos da PostgreSQL listo para usar desde la API

    Base de datos

    Supabase crea un proyecto con PostgreSQL, tablas, tipos de datos, consultas y seguridad configurable.

    SDK de Python

    Desde FastAPI usaremos el cliente de Supabase para hacer insert, select, update y delete.

    API realista

    El backend deja de ser un prototipo de memoria y empieza a parecerse a una aplicacion desplegable.

    7 · Tabla

    Primero creamos la tabla items en Supabase

    create extension if not exists "pgcrypto";

create table if not exists public.items (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  description text,
  price numeric(10, 2) not null check (price >= 0),
  available boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists idx_items_created_at
  on public.items (created_at desc);

create or replace function public.set_updated_at()
returns trigger
language plpgsql
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

drop trigger if exists trg_items_updated_at on public.items;

create trigger trg_items_updated_at
before update on public.items
for each row
execute function public.set_updated_at();

    8 · Tipos SQL

    La base de datos tambien valida la forma de los datos

    uuid

    Identificador unico generado por PostgreSQL con gen_random_uuid(). Evita depender de contadores manuales dentro de Python.

    timestamptz

    Fechas con zona horaria. created_at y updated_at quedan generados por el servidor para tener una fuente de tiempo confiable.

    numeric, text, boolean

    Definen precio, texto y disponibilidad. El check (price >= 0) protege contra valores invalidos incluso si el backend falla.

    9 · Seguridad

    Las credenciales no deben quedar escritas directamente en el codigo

    Riesgo

    SUPABASE_URL = "https://mi-proyecto.supabase.co"
SUPABASE_KEY = "clave-secreta-en-el-codigo"

    Si este archivo se sube a un repositorio, la clave queda expuesta junto con el proyecto.

    Practica segura

    SUPABASE_URL = settings.supabase_url
SUPABASE_KEY = settings.supabase_key

    El codigo lee variables de entorno y el archivo privado .env se queda en la maquina local.

    15 · app/schemas/item_schema.py

    Los schemas de la Clase 2 se adaptan a la tabla real

    from datetime import datetime
from uuid import UUID

from pydantic import BaseModel, Field


class ItemBase(BaseModel):
    name: str = Field(min_length=2, max_length=80)
    description: str | None = None
    price: float = Field(gt=0)
    available: bool = True


class ItemCreate(ItemBase):
    pass


class ItemUpdate(BaseModel):
    name: str | None = Field(default=None, min_length=2, max_length=80)
    description: str | None = None
    price: float | None = Field(default=None, gt=0)
    available: bool | None = None


class ItemResponse(ItemBase):
    id: UUID
    created_at: datetime
    updated_at: datetime

    16 · app/services/item_service.py

    La capa de servicio reemplaza el acceso directo a items_db

    from app.database.supabase_client import supabase
from app.schemas.item_schema import ItemCreate


TABLE_NAME = "items"


def create_item(item: ItemCreate) -> dict:
    payload = item.model_dump()
    response = supabase.table(TABLE_NAME).insert(payload).execute()
    return response.data[0]


def list_items() -> list[dict]:
    response = (
        supabase.table(TABLE_NAME)
        .select("*")
        .order("created_at", desc=True)
        .execute()
    )
    return response.data

    17 · Filtros y cambios parciales

    .eq() selecciona la fila correcta y exclude_unset evita sobrescribir campos

    # Continuacion de app/services/item_service.py
from fastapi import HTTPException, status

from app.schemas.item_schema import ItemUpdate


def get_item(item_id: str) -> dict:
    response = (
        supabase.table(TABLE_NAME)
        .select("*")
        .eq("id", item_id)
        .execute()
    )
    if not response.data:
        raise HTTPException(status_code=404, detail="Item no encontrado")
    return response.data[0]


def update_item(item_id: str, item: ItemUpdate) -> dict:
    payload = item.model_dump(exclude_unset=True, exclude_none=True)
    if not payload:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="No hay campos para actualizar",
        )

    response = (
        supabase.table(TABLE_NAME)
        .update(payload)
        .eq("id", item_id)
        .execute()
    )
    if not response.data:
        raise HTTPException(status_code=404, detail="Item no encontrado")
    return response.data[0]


def delete_item(item_id: str) -> dict:
    response = (
        supabase.table(TABLE_NAME)
        .delete()
        .eq("id", item_id)
        .execute()
    )
    if not response.data:
        raise HTTPException(status_code=404, detail="Item no encontrado")
    return {"message": "Item eliminado"}

    18 · app/routes/item_routes.py

    Las rutas conservan el contrato HTTP y delegan el trabajo al servicio

    from fastapi import APIRouter, status

from app.schemas.item_schema import ItemCreate, ItemResponse
from app.services import item_service


router = APIRouter(prefix="/items", tags=["items"])


@router.post(
    "/",
    response_model=ItemResponse,
    status_code=status.HTTP_201_CREATED,
)
def create_item(item: ItemCreate):
    return item_service.create_item(item)


@router.get("/", response_model=list[ItemResponse])
def list_items():
    return item_service.list_items()

    19 · app/routes/item_routes.py

    El UUID llega por la URL y se usa para filtrar en Supabase

from uuid import UUID

from app.schemas.item_schema import ItemUpdate


@router.get("/{item_id}", response_model=ItemResponse)

    22 · Camino completo

    Un request viaja por capas antes de llegar a la base de datos

    1. Cliente Swagger UI o una app envia JSON al endpoint.
    2. Ruta FastAPI recibe la peticion y valida parametros.
    3. Schema Pydantic verifica tipos, campos obligatorios y respuesta.
    4. Servicio La funcion decide que operacion de Supabase ejecutar.
    5. Supabase PostgreSQL inserta, lee, actualiza o elimina filas.
    6. Respuesta La API devuelve JSON con el resultado persistido.

    23 · Pydantic a diccionario

    Supabase espera diccionarios; Pydantic entrega objetos

    24 · Errores comunes

    Cuando algo falla, revisa por capa

    .env

    Si las variables no cargan, revisa nombres, carpeta actual y que el archivo no tenga comillas raras.

    401 / 403

    La clave puede ser incorrecta o no tener permisos para ejecutar la operacion solicitada.

    RLS

    Si Supabase bloquea inserts o selects, revisa las politicas de Row Level Security de la tabla.

    UUID

    Si el ID no tiene formato valido, FastAPI responde antes de consultar la base de datos.

    Uvicorn

    Si aparece "Could not import module", ejecuta el comando desde la carpeta que contiene app/.
