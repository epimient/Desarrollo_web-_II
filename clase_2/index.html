    API de Items Academicos

    Modelos, validaciones y estructura correcta

    Hoy la API deja de ser un archivo suelto y empieza a parecerse a un backend real: contratos de datos, errores correctos, documentacion automatica y carpetas con responsabilidades.

    Idea central

    Una API profesional no solo responde datos. Tambien decide que acepta, que devuelve, como comunica errores y como organiza su codigo para crecer.

    1 · Proposito de la clase

    De consumir una API a construir una API mantenible

    Venimos de

    • Consumir una API externa con requests.
    • Crear una API sencilla con FastAPI.
    • Escribir todo en un mismo archivo para aprender rapido.

    Vamos hacia

    • Validar lo que entra.
    • Controlar lo que sale.
    • Manejar errores con codigos HTTP.
    • Separar rutas, esquemas, servicios y configuracion.

    5 · Concepto 1

    Que es Pydantic?

    Pydantic es la libreria que FastAPI usa para declarar modelos de datos. Un modelo describe la forma que deben tener los datos que entran o salen.

    En palabras simples: Pydantic nos permite decirle a Python "este dato debe tener esta forma".

    Referencia oficial

    FastAPI documenta que para declarar un cuerpo de solicitud se usan modelos de Pydantic, y que esos tipos permiten conversion, validacion y documentacion automatica.

    FastAPI · Request Body

    6 · Primer contrato

    Modelo base para crear un item

    from pydantic import BaseModel, Field


class ItemCreate(BaseModel):
    name: str = Field(min_length=3, max_length=80)
    description: str | None = None
    category: str
    source: str | None = None

    BaseModel permite crear modelos de datos.

    Field agrega reglas como longitud minima o maxima.

    str | None = None significa que el campo es opcional.

    category: str es obligatorio porque no tiene valor por defecto.

    7 · Validaciones con Field

    Las reglas viven cerca de los datos

    Ejemplo

    name: str = Field(min_length=3, max_length=80)
category: str = Field(min_length=3, max_length=50)

    No escribimos un if manual para revisar el largo del nombre. FastAPI y Pydantic lo hacen al recibir el request.

    Referencia oficial

    FastAPI muestra que Field se importa desde pydantic y permite declarar validaciones dentro de los atributos del modelo.

    9 · Concepto 2

    Por que no usar el mismo modelo para todo?

    Modelo tentador, pero problematico

    class Item(BaseModel):
    id: int
    name: str
    description: str | None = None
    category: str
    source: str | None = None

    Problema

    Al crear un item, el cliente no deberia enviar el id. Ese identificador lo genera la base de datos o la logica interna.

    Pero cuando la API responde, el cliente si necesita recibir el id. Por eso separamos modelos.

    10 · Modelos sugeridos

    app/schemas/item_schema.py

    from pydantic import BaseModel, Field


class ItemCreate(BaseModel):
    name: str = Field(min_length=3, max_length=80)
    description: str | None = None
    category: str = Field(min_length=3, max_length=50)
    source: str | None = None


class ItemUpdate(BaseModel):
    name: str | None = Field(default=None, min_length=3, max_length=80)
    description: str | None = None
    category: str | None = Field(default=None, min_length=3, max_length=50)
    source: str | None = None


class ItemResponse(BaseModel):
    id: int
    name: str
    description: str | None = None
    category: str
    source: str | None = None


class ExternalItemResponse(BaseModel):
    external_id: int
    name: str
    source: str

    11 · Separacion de modelos

    Cada modelo responde una pregunta distinta

    ItemCreate

    Que puede enviar el cliente cuando crea?

    No incluye id.

    ItemUpdate

    Que puede enviar el cliente cuando actualiza?

    Todos los campos son opcionales.

    ItemResponse

    Que devuelve nuestra API al cliente?

    Si incluye id.

    ExternalItemResponse

    Como adaptamos datos de una API externa?

    Devolvemos solo lo necesario.

    12 · Actualizacion parcial

    ItemUpdate evita obligar al cliente a reenviar todo

    Body valido

    {
  "name": "Nuevo nombre"
}

    Aplicacion en el router

    update_data = item_data.model_dump(exclude_unset=True)

for key, value in update_data.items():
    item[key] = value

    exclude_unset=True incluye solo los campos enviados por el cliente. Asi no borramos accidentalmente description, category o source.

    13 · Concepto 3

    response_model controla la forma de salida

    @router.post(
    "/items",
    response_model=ItemResponse,
    status_code=201
)
def create_item(item: ItemCreate):
    ...
    • El cliente envia datos con forma de ItemCreate.
    • La API responde datos con forma de ItemResponse.
    • La documentacion queda alineada con el contrato.

    Referencia oficial

    FastAPI usa response_model para documentar, validar, convertir y filtrar los datos de salida.

    FastAPI · Modelo de Response

    14 · Seguridad de respuesta

    El modelo de respuesta tambien protege lo que exponemos

    Dato interno

    user = {
    "id": 1,
    "name": "Laura",
    "email": "laura@email.com",
    "password": "123456"
}

    Contrato publico

    class UserResponse(BaseModel):
    id: int
    name: str
    email: str

    Si la ruta usa response_model=UserResponse, el campo password no forma parte de la salida publica.

    15 · Concepto 4

    Codigos de estado HTTP: la API dice que paso

    200OK

    Consulta o actualizacion exitosa.

    201Created

    Se creo un recurso.

    204No Content

    Se elimino algo y no se devuelve cuerpo.

    400Bad Request

    Problema logico en la solicitud.

    404Not Found

    El recurso no existe.

    422Unprocessable Entity

    Fallo validacion de Pydantic.

    16 · status_code

    El codigo esperado se declara en el decorador

@router.post(

    status_code=status.HTTP_201_CREATED

    Referencia oficial

    FastAPI permite declarar status_code en operaciones como @app.get(), @app.post(), @app.put() y @app.delete().

    17 · Concepto 5

    Errores profesionales con HTTPException

    Improvisado

    return {"error": "No encontrado"}

    El cliente recibe un JSON, pero no necesariamente un codigo HTTP correcto.

    Correcto

    raise HTTPException(
    status_code=status.HTTP_404_NOT_FOUND,
    detail="El recurso solicitado no existe"
)

    La ejecucion se interrumpe y FastAPI devuelve una respuesta HTTP clara.

    18 · Error como respuesta HTTP

    HTTPException no se retorna: se lanza

    FastAPI explica que HTTPException es una excepcion normal de Python, con datos adicionales relevantes para APIs. Por eso se usa raise. 

    {
  "detail": "El recurso solicitado no existe"
}

    19 · Concepto 6

    Por que no construir toda la API en un solo archivo?

    Cuando todo esta en main.py

    • Rutas.
    • Modelos.
    • Consumo de API externa.
    • Conexion a base de datos.
    • Variables de configuracion.
    • Logica de negocio.

    Que pasa despues

    El archivo crece, se vuelve confuso y cada cambio obliga a tocar el mismo lugar. Separar responsabilidades hace que el proyecto sea mas facil de explicar y mantener.

    26 · Paso 4

    Crear router de items

    from fastapi import APIRouter, HTTPException, status
from app.schemas.item_schema import ItemCreate, ItemUpdate, ItemResponse

router = APIRouter(
    prefix="/items",
    tags=["Items"]
)

items_db = []
current_id = 1

    APIRouter agrupa rutas.

    items_db simula una base de datos temporal.

    current_id genera identificadores simples mientras no usamos una base real.

    27 · Listar y consultar

    Endpoints GET

    @router.get("/", response_model=list[ItemResponse])
def get_items():
    return items_db


@router.get("/{item_id}", response_model=ItemResponse)
def get_item(item_id: int):
    for item in items_db:
        if item["id"] == item_id:
            return item

    raise HTTPException(
        status_code=status.HTTP_404_NOT_FOUND,
        detail="El item solicitado no existe"
    )

    Si el usuario visita /items/hola, FastAPI intentara convertir item_id a entero y devolvera error de validacion.

    28 · Crear

    Endpoint POST

    @router.post("/", response_model=ItemResponse, status_code=status.HTTP_201_CREATED)
def create_item(item: ItemCreate):
    global current_id

    new_item = {
        "id": current_id,
        "name": item.name,
        "description": item.description,
        "category": item.category,
        "source": item.source
    }

    items_db.append(new_item)
    current_id += 1

    return new_item

    El cuerpo entra como ItemCreate; la respuesta sale como ItemResponse y se documenta como 201 Created.

    29 · Actualizar

    Endpoint PUT

    @router.put("/{item_id}", response_model=ItemResponse)
def update_item(item_id: int, item_data: ItemUpdate):
    for item in items_db:
        if item["id"] == item_id:
            update_data = item_data.model_dump(exclude_unset=True)

            for key, value in update_data.items():
                item[key] = value

            return item

    raise HTTPException(
        status_code=status.HTTP_404_NOT_FOUND,
        detail="No se puede actualizar porque el item no existe"
    )

    30 · Eliminar

    Endpoint DELETE

    @router.delete("/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_item(item_id: int):
    for index, item in enumerate(items_db):
        if item["id"] == item_id:
            items_db.pop(index)
            return

    raise HTTPException(
        status_code=status.HTTP_404_NOT_FOUND,
        detail="No se puede eliminar porque el item no existe"
    )

    204 No Content comunica que la eliminacion fue exitosa y que no habra cuerpo de respuesta.

    31 · Paso 5

    Servicio externo para PokéAPI

    import requests
from fastapi import HTTPException, status


def get_pokemon_from_api(pokemon_name: str):
    url = f"https://pokeapi.co/api/v2/pokemon/{pokemon_name.lower()}"

    response = requests.get(url)

    if response.status_code == 404:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="El pokemon solicitado no existe en la API externa"
        )

    if response.status_code != 200:
        raise HTTPException(
            status_code=status.HTTP_502_BAD_GATEWAY,
            detail="Error al consultar la API externa"
        )

    data = response.json()

    return {
        "external_id": data["id"],
        "name": data["name"],
        "source": "pokeapi"
    }

    32 · Separar router y servicio

    El servicio no define rutas: resuelve la logica externa

    Responsabilidad del router

    Recibir solicitudes HTTP, validar parametros, declarar modelos de respuesta.

    Responsabilidad del servicio

    Consultar PokéAPI, interpretar errores externos y adaptar la respuesta.

    No devolvemos la respuesta cruda de PokéAPI porque tiene demasiados campos. La adaptamos al contrato ExternalItemResponse.

    33 · Paso 6

    Router externo

    from fastapi import APIRouter
from app.schemas.item_schema import ExternalItemResponse
from app.services.external_service import get_pokemon_from_api

router = APIRouter(
    prefix="/external",
    tags=["External API"]

@router.get("/pokemon/{pokemon_name}", response_model=ExternalItemResponse)

    42 · Errores comunes

    Problemas esperados y como leerlos

    Ruta no aparece

    Falta app.include_router(items.router).

    ModuleNotFoundError: app

    Se ejecuto uvicorn desde una carpeta incorrecta.

    Modelo de respuesta equivocado

    Usar ItemResponse, no ItemCreate, al crear.

    PUT borra datos

    Falta exclude_unset=True en model_dump().

    Error como texto

    Usar raise HTTPException(...), no return "No encontrado".
